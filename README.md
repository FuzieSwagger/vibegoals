# VibeGoals — трекер целей для двоих

Онлайн-трекер заработка на вайбкодинге: две цели (≈ $500 к февралю и $1000+
к лету), два участника, общий прогресс и график. Чистый HTML, CSS и
Vanilla JavaScript — без фреймворков, зависимостей и сборки.

- **Цели.** Две цели с суммой и дедлайном. По умолчанию: $500 к 1 февраля
  2027 и $1000 к 1 июня 2027. Всё меняется в настройках.
- **Два участника.** Вкладки «Денис», «Глеб» и «Вместе». В командном режиме
  цель умножается на число участников: $500 личных = $1000 общих.
- **Записи о заработке.** Сумма, дата, кто, источник и заметка. Удаление —
  с подтверждением.
- **Прогресс и темп.** Полоса цели с отметкой «план на сегодня», статус
  («в графике» / «немного отстаём» / «отстаём»), сколько нужно в неделю и
  прогноз даты закрытия цели по текущему темпу.
- **График.** Накопленный заработок по дням, линия плана, линия «сегодня» и
  подсказка при наведении. Нарисован вручную на SVG.
- **Достижения.** Девять бейджей от первого доллара до $1000.
- **Экспорт / импорт.** Полный JSON-снимок состояния и сброс данных.
- **Тёмная тема**, адаптив, поддержка `prefers-reduced-motion`.

## Быстрый старт

Нужен только Node.js 18+.

```bash
cd goal-tracker
node server.js
```

Откройте <http://localhost:8787>. Сервер раздаёт статику и хранит общее
состояние в `data/state.json` (файл создаётся сам).

Порт можно поменять:

```bash
# Windows PowerShell
$env:PORT=9000; node server.js

# macOS / Linux
PORT=9000 node server.js
```

## Как включить общий прогресс с Глебом

1. Запустите `node server.js` на машине, которая доступна обоим (или на
   VPS/домашнем сервере), либо откройте доступ по локальной сети — сервер
   слушает `0.0.0.0`.
2. Узнайте адрес: `http://<IP-машины>:8787` (в локальной сети) или ваш
   домен при деплое.
3. Откройте трекер у себя и у Глеба. Если страница открыта с того же сервера
   (`http://` или `https://`), адрес подставится автоматически. Для отдельного
   сервера зайдите в **Настройки → Синхронизация** и укажите адрес вручную.

Дальше клиент сам отправляет изменения (`POST /api/state`) и раз в 30 секунд
подтягивает свежие (`GET /api/state`). Индикатор в футере показывает статус:
локально, синхронизировано или офлайн.

Слияние данных безопасно для двоих: записи объединяются по `id`, удаления
хранятся как «надгробия» и не возвращаются, настройки берутся из состояния
с более свежим `updatedAt`. Конфликтов «кто последний — тот прав» для записей
нет: обе записи сохраняются.

## Режим без сервера

Можно открыть `index.html` напрямую в браузере: данные будут лежать в
`localStorage` этого браузера, синхронизации не будет. Это удобно для
проверки, но общий прогресс так не работает — нужен сервер.

```

├── style.css         стили
├── app.js            логика, график, синхронизация
```

## API

| Метод | Путь          | Описание                                  |
| ----- | ------------- | ----------------------------------------- |
| GET   | `/api/state`  | текущее состояние                         |
| POST  | `/api/state`  | прислать состояние, получить объединённое |
| GET   | `/api/health` | проверка живости и типа хранилища         |

Ограничения: тело запроса до 1 МБ, CORS открыт (`*`), каталог `data/`
статикой не раздаётся. Запись в `state.json` атомарная (temp + rename).
Одновременные POST обрабатываются последовательно, поэтому записи двоих
не затирают друг друга.

## Данные

```json
{
  "version": 1,
  "startDate": "2026-11-01",
  "people": [{ "id": "denis", "name": "Денис", "color": "#4ade80" }],
  "goals": [{ "id": "feb", "label": "К февралю", "target": 500, "deadline": "2027-02-01" }],
  "entries": [
    {
      "id": "uuid",
      "personId": "denis",
      "amount": 25,
      "date": "2026-11-09",
      "source": "Заказ",
      "note": "лендинг для кофейни"
    }
  ],
  "deleted": [],
  "updatedAt": 1762700000000
}
```

`deleted` — список id удалённых записей; нужен, чтобы удаление не «воскресло»
при синхронизации.

## Деплой на Render

Бесплатный инстанс Render засыпает после простоя и теряет локальные файлы,
поэтому состояние хранится не в `data/state.json`, а в бесплатном
[Upstash Redis](https://upstash.com) — сервер сам переключается на него,
если заданы переменные окружения:

| Переменная                   | Значение                                      |
| ---------------------------- | --------------------------------------------- |
| `UPSTASH_REDIS_REST_URL`     | REST URL базы из консоли Upstash               |
| `UPSTASH_REDIS_REST_TOKEN`   | REST token той же базы                         |
| `STATE_KEY`                  | необязательно, по умолчанию `vibegoals:state`  |

Порядок:

1. Зарегистрируйтесь в Upstash, создайте бесплатную Redis-базу (регион
   ближе к вам), откройте вкладку **REST API** и скопируйте URL и токен.
2. Запушьте папку `goal-tracker` в отдельный GitHub-репозиторий.
3. В Render: **New → Blueprint**, выберите репозиторий. Render прочитает
   `render.yaml`, создаст web service и спросит обе переменные Upstash.
4. Дождитесь деплоя и откройте выданный адрес вида
   `https://vibegoals-xxxx.onrender.com`.
5. Откройте адрес на обоих устройствах — синхронизация включится сама.

Проверка хранилища: `GET https://<адрес>/api/health` должен вернуть
`{"ok":true,"storage":"upstash"}`. Без переменных Upstash сервер работает
с локальным файлом — это удобно для разработки, но не для Render.

Любой другой хостинг с Node.js тоже подойдёт: команда запуска `node server.js`,
порт берётся из `PORT`. Для VPS поставьте сервер за reverse proxy
(Caddy/Nginx) и включите HTTPS.

## Примечания

- Даты считаются в полдень локального времени, чтобы переход на летнее время
  не сдвигал дни.
- `state.json` не хранится в репозитории; при необходимости сделайте резервную
  копию через «Экспорт» или скопируйте файл.
